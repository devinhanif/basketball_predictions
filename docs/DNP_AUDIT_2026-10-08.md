# DNP-row audit (2026-10-08)

Question: `player_game_stats` DNP rows have `minutes` NULL and pts/reb/ast = 0 (not NULL).
Commit 8db734f found this dragged the forward season-average low. Does it contaminate the
backtest results? Read-only audit; no source changed. Queries: `duckdb.connect('nba.duckdb', read_only=True)`.

## 2. Per-component findings

Legend for the four questions: (1) DNP rows in the scored LABEL set; (2) DNP zeros in the
season-avg BASELINE; (3) DNP rows in the sim's rate builders; (4) asymmetry.

### A. Props baselines `nba/props/baselines.py:36-48`
(2) YES: `AVG(pgs.{stat}) OVER (... UNBOUNDED PRECEDING AND 1 PRECEDING)` over every row, DNP zeros
included; `STDDEV_SAMP` likewise. Note the window is player career-to-date, not within-season, despite
the column name `season_avg_prior`. (1) YES (see C/D). The mean is the correct estimator of the
*unconditional* target (zeros included in both), so on the scored set the baseline is unbiased in
aggregate; it is biased only for "played" rows. Its Normal spread is inflated by the zero spike.

### B. As-of features
- `nba/props/minutes.py:182,209-216`: `played = minutes > 0`; mean/std minutes computed on played
  rows only; play rate separate. DNP-aware by design. **Unaffected.**
- `nba/props/stat_models.py:74-87,114-119,220-225`: rate = SUM(stat)/SUM(minutes); NULL minutes are
  ignored by SUM and DNP stat is 0, so DNP rows add nothing to either side. **Unaffected** (correct).
- `nba/features/player_possession_features.py:179-217,454` (`shot_share_prior`, zone mix, FT trips):
  `per_game` selects every `player_game_stats` row incl DNP; `team_n_fga` of the whole game is added
  to the denominator for DNP games while the player's n_fga is 0. So shot_share is deflated by the
  fraction of games missed. **Affected (in the sim's rate builders).**
- `nba/features/player_rebound_assist_features.py:109-160`: same pattern: `team_missed_fga`,
  `opp_missed_fga`, `teammate_fgm` of the full team game are summed for games the player did not play,
  so `orb_rate/drb_rate/ast_rate_prior` are deflated for DNP-prone players. **Affected.**
- `nba/features/player_features.py:63-73`, `time_decay.py:190` (`SUM(num)/SUM(den)` over all rows):
  `minutes` as denominator is NULL-safe, other denominators not audited. **Mostly unaffected /
  unverified for non-minutes denominators.**
- `nba/sim/usage_redistribution.py:281` coalesces `minutes` to 0 for the roster frame, line 616
  filters `COALESCE(minutes,0) > 0` for played games. Handled explicitly. **Unaffected** (mechanism
  also shown inert, n=0).

### C. Sim evals
`nba/eval/player_points_sim_eval.py` and `player_reb_ast_sim_eval.py`:
- (1) Label set = all `player_game_stats` rows for the game (`roster`/`roster_reb` built from rows,
  lines points:181-183, reb_ast:~167-173; y = `COALESCE(stat,0)`). DNP rows ARE scored, y=0. The
  roster is "who has a row", which includes DNPs (and excludes players with no row at all).
- (2) Baseline = `build_baseline_features` (A) incl zeros -> consistent with the label.
- (3) Sim inputs: `projected_minutes` from `predict_minutes(...).mean()` (hurdle; the mean already
  carries P(DNP)), then `player_attribution.py:299-300` weight = `shot_share * minutes/240`, where
  `shot_share` (B) is ALSO deflated by missed games. DNP discount is applied twice for DNP-prone
  players (once in the rate denominator, once in projected minutes). Team totals are fixed by team
  ratings and weights are renormalised, so the effect is a relative shift of volume from
  intermittent players to regulars.
- (4) Direction: baseline is internally consistent (unbiased on the all-rows target); sim has a
  likely double-discount that under-predicts intermittent players, partly offset by renormalisation.
  Measured aggregate sim mean bias is small (reb -0.12, pts -0.01, ast +0.29; 600 games) but
  aggregate bias cannot reveal per-bucket structure and ast +0.29 means it is not uniformly low.
  Separately, roster-from-actual-box-score (documented, `player_points_sim_eval.py:29-42`) tells the
  sim who has a row; players with no row at all (inactive) are absent, which favours the sim. That is
  an existing, documented lineup-membership leak, not a DNP-zero issue, but it interacts: the sim
  and savg are scored on rows chosen using post-game information.

### D. Props run `nba/props/run.py` (`_target_frame` 171-209)
Labels include DNP rows at 0; baselines include zeros; the model's mean = minutes-mean (incl P(DNP)) x
rate, a coherent unconditional prediction. **Unaffected in direction (apples to apples, all rows)**.
Caveat: pooled CRPS is dominated by easy DNP rows where mass near 0 wins; "bias within +/-0.5" and
coverage are therefore properties of the unconditional target, not of per-minute performance.

### E. Routing and SB buckets
`model_routing.py` and `routed_eval.py` are pure functions over supplied arrays/labels; they inherit
the upstream contamination and add none. The bucket labels, however, are DNP-contaminated (section 1):
"intermittent" is a ~32% DNP group, so "sim wins intermittent" (pts/reb) is a statement about
DNP-heavy bench rows, where the two models handle P(play) differently (savg: empirical zero fraction
over career; sim: hurdle model + double discount). It is NOT evidence about stat intermittency.
Also `model_routing.py:185-203` describes joining the *latest* SB row per player; if anyone ran that
form, the bucket used future games (leak). `routed_eval.py` docstring says per-row as-of; I did not
verify which form produced T005-T030.

## 5. Proposed fix (not implemented)

Single source of truth in `schema.sql`/ingest, no per-module guards:
1. Add `played BOOLEAN` (= `minutes IS NOT NULL AND minutes > 0`) and a view
   `player_game_stats_played AS SELECT * FROM player_game_stats WHERE played`. Keep the base table
   (labels for unconditional targets need the DNP rows).
2. Convention: every as-of rate/baseline/SB builder reads `player_game_stats_played` for numerators AND
   denominators; the DNP indicator is carried separately as P(play) (already `minutes.py`). Targets
   either stay unconditional (all rows) or conditional (played) but are declared per metric, and the
   report prints both (as 8db734f does forward).
3. Rate builders: restrict `per_game` in `player_possession_features.py` and
   `player_rebound_assist_features.py` to played rows; then drop the double discount by deciding where
   P(play) enters (rates conditional on playing x projected minutes that already contain P(play), OR
   conditional minutes with explicit Bernoulli(P(play)) draw in the sim).
4. Do not NULL stats at ingest: `NULL` poisons the `COALESCE`d NaN paths documented in
   `props/run.py:172`, and it destroys the unconditional label. A `played` column is the cleaner
   change. Add a hypothesis/fixture test that planting a DNP row (minutes NULL, stats 0) does not
   change any played-only baseline or rate (mirror the planted-future-game test in
   `tests/ml/test_player_rebound_assist_features.py`).
