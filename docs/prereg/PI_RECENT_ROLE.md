## Hypothesis
`pi` is fit on `COMMON_FEATURES` only (`nba/props/context_residual.py` lines 690-721). It holds `min5/min10/min40` (exponentially weighted) and the last-game starter flag, but not the minutes of the last game, the last three or five games, or the load in the last 3 and 7 days. The `short` label is "minutes < 0.5 x min10", measured against a stale projection, so a player whose role just collapsed (2 minutes last night, `min10` still 18) is exactly the row `pi` cannot see. Same carrier as RECENT_ROLE (T455-T458: P(play) with the same five columns, -0.0094/-0.0120 for production's recency columns and a further -0.0075/-0.0046, 2025 holdout PASS -0.0205), applied to the model that sets the lower tail. Prediction: `pi` improves (log loss, AUC), and the integer CRPS of the mixture improves most where the lower tail lives (realised minutes < 5, bench).

## Honest prior (read first)
* Headroom is large, capture is small. Descriptive, from the stored arrays and this harness's `ORACLE` arm (pi := the realised short flag, which no forecast can know): integer CRPS vs A0 pts -0.1501 [-0.1609,-0.1395] (2023) / -0.1457 [-0.1563,-0.1355] (2024); reb -0.0600 / -0.0610; ast -0.0245 / -0.0235; fg3m -0.0140 / -0.0120 (smoke run, deltas of A0 against the oracle; the audit quoted -0.1626 / -0.1564 for pts with a different oracle construction I did not reproduce). The current `pi` (AUC 0.855, mean 0.0905 / 0.0923 vs observed 0.1061 / 0.1018) earns -0.0126 / -0.0107 of that over "off". So a CRPS gain of -0.005 on pts needs `pi` to capture about 3.3% of the remaining oracle gap.
* My estimate that a stat reaches the floor in both seasons: **pts about 0.25** (the audit said 0.15; the P(play) gain of the same columns was large, but the short flag is rarer, 10% vs 17%, and production already carries `min5` which holds 14% weight on the last game), **reb about 0.05, ast about 0.02, fg3m about 0.01** (their oracle gaps are 2.5x, 6x and 10x smaller than pts, so even a pts-sized capture falls under the floor). Most likely outcome: a real but sub-floor improvement on pts (-0.002 to -0.004) and nothing on the others. The rule treats that as NOT a pass (the floor protects against a gain nobody could use), and says so now.
* The paired noise floor of this comparison is small: pi is the only thing that moves, so CIs are tight (the shuffled-label noise run below: CI half-width 0.0007-0.0010 on pts). The floor, not the CI, is the binding constraint.
* Dependence: if this passes, the NEAR_MISS_BUNDLE's gate and SEQ routing inherit a better `pi` (audit sequencing advice: C1, then the bundle). That is not part of this rule.

## Primary test
Rows: the PLAYED rows of the stored components (n = 27,619 rows / 1,318 games in 2023; 27,701 / 1,320 in 2024; identical for the four stats), rows with `n_prior >= 5`, walk-forward month blocks 2023-10 .. 2025-06 (18 blocks), each fitted strictly on rows dated before the block (2022 is warm-up).
Arms (every arm is the same code with a different `pi` vector; everything else is the stored component):
* **A0**: the stored `row_pi`; the control refit (COMMON_FEATURES only, `walk_pi`) is gated equal to it (0.0).
* **CAND**: `pi` from a production-parameter binary LightGBM on COMMON_FEATURES + the 5 R columns, one classifier per block shared across stats (as production and `collect_pi`), `fit_short_state`, `predict_pi` (clip [0.005, 0.5]) unchanged. `w_q` (short-minutes ratio quantiles) does not depend on the classifier, so the stored per-block `wq_*` is reused (stated; the control refit equals the stored `pi` exactly).
* **PL** (past-only placebo, `research/recent_role/placebo.py`, 4 tests from RECENT_ROLE): COMMON_FEATURES + the five R columns replaced, per row, by the five values of ONE uniformly drawn strictly-earlier played row of the same player-season (NaN for a player-season's first row, 2.2% of A0 rows). Disclosed difference from RECENT_ROLE: the draw is over the player's PLAYED rows (the frame here is the production played-row frame), not the Cell-P universe that includes DNP rows.
* **SHUF_CTRL, SHUF_CAND**: classifier trained on ONE permutation of the training short labels per block (global over the training rows, `default_rng([0, block])`), identical for both arms (label hash equal, asserted at run time), scored against the real outcomes. The permutation applies to the classifier labels only; `w_q` uses the real flag.
* **ORACLE** (descriptive, not a pass condition): pi := the realised short flag.
Metric: integer-support CRPS of the 199-point quantile grid mapped to integers (`to_integer_support`), as A0 is scored; CAND - A0 per row, mean over rows, game-clustered percentile CI and two-sided clustered-bootstrap p (`WE.delta_stats`); MDE = half the CI width. BH (`bh_adjust`) over the four stats within each season; family m = 4, declared.

## Pass rule (all must hold, per stat)
1. 2023 (select): delta <= -0.005, CI upper < 0, p_BH <= 0.05.
2. 2024 (report): delta <= -0.005, CI upper < 0, p_BH <= 0.05. (BH in both seasons is stricter than RECENT_ROLE Stage 2a, which used it in 2024 only; I chose the stricter reading before scoring.)
3. Calibration of `pi` (short flag, 10 equal-width bins, ECE of the clipped `pi`): ECE(CAND) - ECE(A0) <= +0.005 in both seasons. (`pi` is shared by the four stats: one guard.)
4. Slices (per stat, per season, delta = CAND - A0, a slice with n < 300 is reported and cannot fail): minutes < 5 (realised), bench (as-of `starter10 < 0.5`), playoffs (game_id prefix `004`), cold start (`n_prior < 10`). None with n >= 300 worse than +0.01. Descriptive also: starter, short, not short, minutes < 10.
5. Placebo: CAND - PL <= -0.003 in each season for that stat.
6. Shuffled-label check: FAILS if CAND_shuf - CTRL_shuf <= -0.001 with CI upper < 0 for ANY stat in ANY season (a classifier shared across stats that learns from permuted labels is a pipeline defect, not a per-stat nuance). Unit tests: arms use identical permuted labels, scoring is on real labels, and on a planted-signal frame the check passes with the permutation and FAILS when it is switched off (`permute=False`).
7. Gate and plants all pass (below); missingness within limit.
Naming: if a stat passes, the claim is "the recent-role set in the short-minutes classifier"; no attribution to one column is made (no knockout arm; one family by construction).

## What each choice protects against
* Control refit equal to the stored `pi` (0.0): crediting refit noise or a changed pipeline to the new columns. One classifier, production parameters, no tuning: tuning on the report season.
* Floor -0.005 and the oracle-capture arithmetic in the prior: a statistically clear gain nobody could use; stating the sub-floor outcome in advance keeps it from being rescued as "a real effect".
* CRPS on the integer grid for every arm: the support artifact (T114-T118). Game-clustered CI, BH over four stats in both seasons: row-level anti-conservatism and the multiplicity of four stats.
* Past-only placebo and the shuffled-label check that can fail: capacity, player-level scale, a pipeline-manufactured gain (the two WORKLOAD harness defects).
* Slice and calibration guards: a gain bought by mis-calibrating `pi` or by hurting the near-DNP rows the lower tail is for (SEQ blends failed exactly this slice, T442).
* The freeze-commit and holdout-row refusals in the harness: starting from an uncommitted rule; an unlogged holdout touch.
