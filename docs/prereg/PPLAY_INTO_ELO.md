## Hypothesis
Production `rung0_injury_elo` v2 adjusts only for players the T-60 official report lists OUT (full weight) and DOUBTFUL (weight 0.5, fitted coefficient about 0.012, i.e. nothing): `logit p(home) = elo_diff*ln(10)/400 + b*(V_out_away - V_out_home)/10 + g*(V_doubt_away - V_doubt_home)/10`. Questionable, probable and unlisted players count as fully available, although about half of the questionable sit and rest, return and load-management absences are mostly unreported. Weighting each rostered player's as-of value by his probability of missing, from the P(play) R model (which carries recent minutes, DNP streaks, back-to-back and the T-60 report tag), should move win probabilities in games where a valuable player is a game-time or unreported absence.

## The arm, exactly
**Comparator PROD** = production `rung0_injury_elo` v2: features `d_out`, `d_doubt` (`nba.models.injury_elo.build_injury_features`, `configs/injury_elo.yaml`: `ValueConfig` decay 0.97, rate pseudo-minutes 400, minutes pseudo-games 8, prior minutes 8, replacement fraction 0.80; report gated at the real scheduled tip minus 60 min; `doubtful_weight` 0.5), frozen MOV-Elo logit as the offset (`configs/mov_elo_tuned.yaml`), two ridge coefficients (lambda 5 on value/10 units), refit before every calendar month on games strictly before it, coefficients frozen at 0 until 150 signal games, first date dropped as in the production harness. **The stored OOF `data/injury_elo_realtip/oof_predictions.parquet` (n 3,951 games, 2022-24) is reproduced to 1e-9 first; otherwise the run stops.**
**Candidate PP** = identical except the second feature. For game g, team side t:
* Roster `Ros(g, t)`: players with a played box row (minutes > 0) for team t in at least one of t's previous 10 games (any season, so the opening games of a year are covered), whose most recent prior box row is for team t (trade guard), with `n_played_prior >= 5` (R's eligibility; below that the shrunk value is near zero anyway), and **not** in the OUT set of the latest report snapshot stamped at or before the real tip minus 60 minutes (the production `latest_pretip_flagged` rule). This is a pre-tip, box-history population: nothing from tonight's box, minutes or starter flag defines membership (the T484 wound for R's stored scores, which are defined on rows of tonight's box).
* `v_i`: the production as-of value of player i (`asof_values`, games strictly before the date).
* `p_i`: P(play) from **R'** = the R19 construction of PPLAY_MINUTES_VALID (R's frozen columns from `research.eval.recent_role_eval.arm_columns()["R"]` plus the four era channels; LightGBM binary with RECENT_ROLE's parameters, seed 0, no tuning), refit before every calendar month on every row dated strictly before it from 2019-20 on, **trained on the roster population `Ros` itself, with label played = minutes > 0 in tonight's box (0 for a rostered player with no box row)**. This is the population repair the EXPECTED_ABSENCE gate demanded; it is a P(play) model that has never been evaluated (stage 0 below). 2021-22 report features are dropped and `era_report_dropped = 1` on those rows as in PPLAY_MINUTES_VALID rule 4.
* `M_t = sum over Ros(g, t) of v_i * (1 - p_i)`; `d_pp = (M_away - M_home) / 10` (away minus home, as `d_out`).
* Features of PP: **(`d_out`, `d_pp`)**. `d_doubt` is dropped: a doubtful player is in `Ros` and enters through `1 - p_i`, so he is not counted twice. PROD and PP therefore have **two fitted coefficients each, the same ridge, the same offset, the same walk**: the contrast is information, not capacity. OUT players keep their full production weight via `d_out`.
**Controls (non-primary):**
* **PP_const**: `p_i` replaced by the season-to-date league play rate of `Ros` players (one number per date). `M_t` is then a constant multiple of the team's healthy-roster value, a depth feature. If PP beats PROD only because it carries roster strength Elo lacks (early-season, roster turnover), PP_const gets the same gain.
* **PP_P0**: `p_i` = production's served hurdle P0 (`forward.predict_slate` constants, no fit) on the same rows. PP minus PP_P0 is what R adds beyond the shrunk trailing play rate.
* **PP_past**: `p_i` = the player's previous `Ros` row's R' (strictly earlier, same season; the gain must be current information).
* **PP_day**: `p_i` permuted among the `Ros` players of one calendar date (non-inert shuffle: a scorer that cannot be hurt is blind).

## Metric, floor, CI, seasons
* **Primary:** paired per-game **log loss**, PP minus PROD (negative is better), also **Brier** and ECE (10 equal-width bins); log loss clipped at [1e-6, 1-1e-6]; one row per game, so the percentile bootstrap (2,000 draws, seed 0) is game-clustered; the date-clustered interval (design effect 1.08-1.23 measured in the EXPECTED_ABSENCE gate) is printed.
* **Floor: log loss <= -0.002 with 95% CI upper < 0, in both 2023 (select) and 2024 (report), Brier point <= 0, ECE worse by no more than +0.005.** One test (m = 1), no family. The floor is the INJURY_ELO_T30 and EXPECTED_ABSENCE floor; production's whole OUT-only gain over MOV-Elo is -0.0081 [-0.0121, -0.0038] (T128, n 3,951), so -0.002 is a quarter of everything the report currently buys.
* **Guards (all must hold in both seasons):** PP minus PP_const <= -0.001 (the gain is availability, not depth); PP minus PP_past <= -0.001; PP_day is worse than PROD (CI lower > 0); no slice with n >= 100 where PP minus PROD > +0.005. Slices fixed now: games with >= 1 rotation player (mean minutes >= 20 over >= 5 prior games) questionable or doubtful at T-60; first 15 team games; second night of a back-to-back (either team); close games (|p_PROD - 0.5| < 0.2, where the gap to Pinnacle sits); games with no rotation player OUT. **Guard thresholds are not sized from a permutation null** (each null draw is a monthly LightGBM walk for R'; K = 50 is a day of Mac CPU); they are flagged as unsized and must be sized before any freeze (BEST_PRACTICES, shuffle-guard rule).
* **Words:** PASS = floor, CI, Brier, ECE, guards and slices in both seasons. FAIL = either season's CI lower bound > -0.002 (a floor-size gain is excluded). INCONCLUSIVE otherwise. A PASS is a candidate for a forward arm, never a production change.

## Playbook check (ratings; gradient-boosted P(play) input)
1. **Information or capacity?** Information in principle (R carries recent minutes, DNP streaks, the report tag and back-to-back), identical capacity by construction (two coefficients, same ridge and offset). The ledger's bound on how much availability information the win probability can use is -0.0008 (T160), which is why the hypothesis is expected to fail.
2. **Enough data for this class?** Elo has a low data appetite (ELO_HISTORY_WINDOW null); R' (trees) needs 2-4 seasons and gets 2019-2024. Data is not the constraint; the effect size is.
3. **Test valid?** As specified, yes: pre-tip box-history roster, real tips, R' trained on its own population, OOF reproduction to 1e-9, planted future, PP_const / PP_past / PP_day controls. Invalid versions to avoid: R scores on rows of tonight's box (outcome-defined population, the opp_adjusted_ridge fingerprint); status defaults for uncovered players (EXPECTED_ABSENCE). One season detects about 0.004-0.005 at 80% power (playbook), more than twice the floor, so a one-season null would be uninformative: a fail of power, not of the idea.
4. **Lineage.** EXPECTED_ABSENCE (same idea, listed players only; gate FAIL, not frozen), INJURY_ELO_T30 (T160/T161 NO SIGNAL), INJURY_REASON, QUESTIONABLE_STREAK and RETURNING_TEAMMATE (closed on power or effect size), RAPM injury-Elo (T176, INVALID stints), production T128, PPLAY_MINUTES_VALID (R19, PRODUCTION_BEATEN T482, WOUNDED T484), RECENT_ROLE_HOLDOUT (T458). **Carried:** real-tip gating, OOF reproduction, past-only and day-shuffle controls, the era handling of 2021-22, missingness by outcome group, planted future, the T484 population wound as the design driver. **Dropped:** status defaults (EXPECTED_ABSENCE), the K = 50 permutation null (unaffordable here; thresholds flagged unsized).
5. **Scored against:** production injury-Elo (primary), MOV-Elo and the de-vigged Pinnacle moneyline (descriptive). The market beats us on game winners by +0.011 to +0.021 log loss; a tweak worth 0.001 cannot reach it.

## What each choice protects against
* Replacing `d_doubt` rather than adding a third term: equal capacity, no double count of doubtful players.
* A pre-tip roster population (not tonight's box): the outcome-dependent coverage that sank EXPECTED_ABSENCE.
* R' trained on its own population: a P(play) model calibrated on dressed players only, whose p for the undressed is extrapolation.
* PP_const: a roster-strength feature mistaken for availability.
* Floor -0.002 and both seasons: a one-season fluke; the floor is a quarter of the report's whole gain.
* Descriptive-only market line: a market comparison that would otherwise tempt a bet claim.
