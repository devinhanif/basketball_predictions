# 2025-26 systems replay through the automated daily process (2026-10-09)

**Status: operational test, NOT a confirmatory touch.** Logged beforehand in `docs/HOLDOUT_ACCESS_LOG.md`
(commit 9f49a21). Binding rules: no selection, tuning, promotion or keep/drop decision from these
numbers; production primary scores are descriptive only (those models' 2025 touch is already spent);
shadow-arm vs production deltas on 2025 are SEALED (computed by the checkpoint/report code for plumbing,
never read or recorded here); Kalshi/market comparisons are descriptive and exploratory.

Tool: `python -m nba.daily.replay_season --season 2025 --db data/rehearsal/replay2025.duckdb`
(`nba/daily/replay_season.py`, tests `tests/daily/test_replay_season.py`). Everything ran on COPIES under
`data/rehearsal/` (git-ignored). `nba.duckdb` was copied once (no writer, no WAL) and never opened for write.
The tree the run used contained the M4 per-game injury-report rule (c1c1b98) and the fixes before it; the
`forward_predictions` write-on-change commit e8669d3 landed AFTER the run (see Storage).

## What the replay does per game date (in order)

1. Results of that date and later are hidden (`nba.daily.rehearsal.truncate_for_replay` once at the start;
   each date's results are restored only after its predictions exist).
2. The pretip job's `nba.daily run` equivalent (`run_daily`) at a fake `now`, once per distinct tip-off
   group, at the last live-job slot (:20 or :50) at least 70 min before that group's tip. Flags as in
   `ops/nba_daily.sh`: `--roster-source recent`, `--log-int-variant`, `--log-lower-tail-variant`,
   `--skip-ingest --skip-injury` (reports are the `player_availability` rows already in the copy; the
   pipeline filters them itself by report stamp <= tip - 60 min and <= 36 h old). Tips are the REAL tip-offs
   (`data/schedule/raw_2025-26.parquet`): 0 of 1,316 games fell back to the 19:00 ET proxy.
   Roster source `recent` (players in each team's last 10 games) because historical official rosters
   do not exist; this understates coverage relative to the live `official` source (see Coverage).
3. T-30 arm: only if the lineup collector has snapshots for the date; it holds 48 rows from 2026-10 only, so
   it was recorded as `skipped: no lineup collector data` on 210/210 dates.
4. Restore that date's results, then the morning job: `settle_pending` (also builds `forward_scores_elig`).
   `checkpoint --descriptive` (look END, season 2025) and `report` once at the end, written to
   `data/rehearsal/replay2025/` (never `data/checkpoints` or `registry_store/reports`).
5. Parlay shadow `evaluate` + `--settle --no-log` against a Kalshi copy (below).

Not replayed (network or no 2025 equivalent): referee collect, market capture, post-game ingest, backups,
the props-analysis report (`nba.parlay analyze`).
Resumable (per-date phase in `data/rehearsal/replay2025/state.json`), streaming (state saved after each phase),
memory-bounded (20-date worker subprocesses holding `data/ops/heavy.lock`, released between chunks; no lock
waits occurred). A step failure is recorded and the replay continues.

Leak audit of the written predictions (independent SQL, read-only): `features_as_of_before` equals the game
date on every row; of 4,705 `rung0_injury_elo` rows, 0 use a report stamped after tip - 60 min (US-Eastern clock,
DST-correct) and the oldest used report is 26.75 h old; every `forward_scores_elig` row has `made_at <= tip - 70 min`.
21.7% of win rows are made inside tip - 60 min (the live cadence predicts every not-yet-tipped game each run);
scoring uses the eligible earlier run. The production win log loss below (0.5915) is within noise of the
already-spent offline confirmation (0.5908, proxy tip), i.e. the automated path reproduces the offline result.
Reports were backfilled, so "as they existed" is by report stamp, not by `pulled_at`.

## Coverage (games and players predicted vs played)

* Games: 1,316 predicted / 1,316 played. `rung0_injury_elo` is primary on 1,310; 6 games had no usable
  report and fell back to `rung0_mov_elo` (`no_report_published_by_tipoff_minus_lead`).
* Player-games with minutes > 0: 28,593 played; 26,460 had a prediction (92.5%), covering 610,724 of 635,137
  minutes (96.2%). 6,221 predicted player-games did not play (DNP; scored as `dnp`, not in the metrics).
  The 2,133 unpredicted player-games are players outside the `recent` last-10-games roster or cut by the
  18-per-team roster cap. Expect better with `official` rosters live.
* Props routing: 11,380 of 468,580 primary prop rows (2.4%) used `recency_fallback` (fewer than 5 prior played
  games); the rest `context_residual`. One `reb` row was `unscorable` (p_ge_full below 99.9% mass).
* Row counts (plumbing only): primary props 117,145 per stat; `_int` 114,300 (reb/ast/fg3m); `_lt` 114,300 (pts);
  recency 117,145 per stat; injury-Elo 4,705; MOV-Elo 4,764 (rows over all runs, append-only).

## Kalshi / parlay shadow replay (descriptive, exploratory)

* Game-winner history exists: `backfill-historical` into a SEPARATE DB (`data/rehearsal/kalshi_2025.duckdb`, public,
  read-only, 1 s rate limit) returned 2,898 settled `KXNBAGAME` markets (2025-04 .. 2026-06), 2,640 in the
  2025-26 window, every one with 60-minute candles (174,132 candle rows). Candle `ts` is the END of the hour, so a
  pre-tip price can be up to 60 min stale and only bid/ask at the hour close is known.
* The replay used a results-hidden working copy (`result`/`settled_ts` NULL) and, for each date, ran
  `nba.parlay evaluate --now <run time>` (forward predictions clipped to made_at <= now, prices to ts < now, game
  already tipped excluded) then `--settle --no-log`. The first 8 dates used every run; the other 202 used the first run
  of the date only (the shadow log keeps the first prediction of the day per ticker and side, and a re-evaluation
  of the same date adds almost nothing). The joint model (`data/parlay/joint_model.json`) was fit on 2022-24 only.
* Result: 5,244 shadow rows (2,622 markets x 2 sides, 1,311 games), all settled, none void; 5,988 contracts
  evaluated incl. repeats; **0 flagged, verdict `no_positive_ev_found` throughout; 0 paper trades**.
  Skips: `game_not_in_slate` (other dates, expected), `unknown_team_abbr` 2 per evaluation (a 2025 preseason
  Guam game, benign), `game_tipped` on the all-run dates.
* Exploratory model vs market on the YES side (n = 2,622 market rows = 1,311 games x 2 complementary markets, 207
  date clusters): Brier model 0.2039 vs market mid 0.1975; paired model minus market **+0.0064 [+0.0023, +0.0104]**;
  log loss +0.0172 [+0.0077, +0.0269]. The market is better; mean ask minus mid is 0.0054. No claim of edge.
* Props markets: 61,105 historical prop markets exist (PTS 17,755, REB 17,570, AST 14,040, 3PT 11,740; 2026-01-17 ..
  2026-06-14, 127 dates) in `data/rehearsal/kalshi_props_2025.duckdb`, but only about a fifth have a `player_id`
  (149 unmatched names) and I pulled NO candles (61k calls, about 17 h at 1 s), so the props parlay replay was
  skipped. Next step if wanted: sample dates plus alias review.

## Settle / checkpoint / report mechanics

* Settle: working on every date (counts over all models: 2,627 win rows, 316,080 prop rows, 73,204 DNP rows in
  `forward_scores`; `forward_scores_elig` statuses scored/dnp/unscorable as above). Idempotent re-run proven in tests.
* Checkpoint: `evaluate_checkpoint(..., "END", season=2025, descriptive=True)` wrote its snapshot (json, md,
  shadow pair parquets) under `data/rehearsal/replay2025/checkpoints/descriptive/`; **contents not read** (sealed).
  The `nba.daily checkpoint` CLI has no `--season` (defaults to 2026) so it cannot do this on a past season.
* Report: `build_report(season=2025)` rendered (4.5 KB, no error lines); not used here beyond that.

## Bugs and findings

Fixed (small, tested, no model-output change):
1. `nba.parlay evaluate --now` stamped shadow rows with the wall clock; now passes the clock to `log_shadow`
   (test `test_parlay_evaluate_stamps_shadow_rows_with_the_replay_clock`).
2. `nba.parlay evaluate` did not clip forward predictions to `--now` (`load_slate(as_of=...)` existed but was not
   wired): a replayed or back-dated evaluate saw later runs. Now `as_of=a.now`; live (no `--now`) unchanged.
   Both edits are already in HEAD (swept into ec1ec13).
3. `build_report` creates tables, so it needs a write handle (replay finalizer fixed; no production change).

Reported only:
4. Worker RSS grows within a chunk (1.3 to 3.3 GB over 20 dates); fine on 8 GB because chunks reset it, but a
   single process over a season would not be. Cause not investigated (DuckDB/polars buffers or cached model objects).
5. Disk growth: model cache unpruned (about 1 GB per season) and `forward_predictions` append volume (above).
6. polars `join_asof` "Sortedness of columns cannot be checked" UserWarning printed on every run from
   `nba/props/context_residual.py:372`, `nba/models/injury_elo.py:221`, `research/sim/usage_redistribution.py:712`
   (benign, noisy logs; suppressed in the replay worker only).
7. The checkpoint CLI cannot target a season other than 2026 (above).
8. The replay predicts once per tip group, not every half hour; superseded earlier runs are not replayed. They do not
   affect the T-60 comparator or scoring, but they do affect storage and the first-prediction-of-the-day parlay rows.
9. Historical Kalshi prices are hourly candles, so live top-of-book spread and staleness are not reproduced.
10. Process note: killing a backgrounded lock-holder with `pkill` skipped its EXIT trap and left a stale
    `data/ops/heavy.lock`; released by hand. The helper `data/rehearsal/run_parlay_pass.sh` traps TERM/INT.

## Reproduce (resumable)

```
uv run python -m nba.daily.replay_season --season 2025 --db data/rehearsal/replay2025.duckdb          # predict+settle, 20-date chunks
uv run python -m nba.kalshi --db data/rehearsal/kalshi_2025.duckdb --rate-limit-s 1.0 backfill-historical \
  --series KXNBAGAME --max-pages 40 --page-limit 1000 --candles --max-candle-markets 3000            # public, read-only
uv run python -m nba.daily.replay_season --season 2025 --db data/rehearsal/replay2025.duckdb \
  --kalshi-db data/rehearsal/kalshi_2025.duckdb --parlay-pass --parlay-runs first
uv run python -m nba.daily.replay_season --season 2025 --db data/rehearsal/replay2025.duckdb --finalize-only
```
Outputs: `data/rehearsal/replay2025/{state.json,summary.json,parlay_summary.json,forward_report.md,checkpoints/,paper_trades.duckdb}`.
