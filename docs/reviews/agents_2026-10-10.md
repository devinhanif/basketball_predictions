Rules every old file carried and every new file keeps: never commit (the main session reviews and
commits); ~600 s no-progress watchdog, so build on `tests/fixtures/loader.py::build_fixture_db` and hand
long jobs to the maintainer with the exact command; DuckDB is single-writer, so `read_only=True` and
never a write connection; the 2025 holdout is never loaded (`season <= 2024` in SQL) and a touch needs a
committed log row first; verification never piped through `tail`/`head`; keys via environment only; no
AI attribution; the output contract (files changed, test results unpiped, exact maintainer command,
honest no-signal note, rows drafted not appended).

## New in the six
- Adversary independence is structural: no write access to `nba/`; any diff to `nba/truth/` goes to it
  before merge; the steward owns `truth/` and does not judge itself.
- The steward's gates are named: the replay oracle (`nba.daily.canonical_dump`, a hash not a tolerance)
  and the layering test (`tests/test_layering.py`).
- The scribe's briefing lists "rules enforced today" and any bypass of a non-negotiable.
- Modeler output is ordered: prereg draft -> main commits -> fit -> result note -> adversary. The
  minimum-data gate is checked against real data before a rule is frozen (non-negotiable 8).

## The team harness
`team.py` (897 lines), `team/tasks.json` and `team/config.json` queued agents by the old names via git
worktrees under `.team/`. Referenced only by `lead.md` and `qa-reviewer.md` (deleted here) and by history
(DECISIONS, DESIGN_RESTRUCTURE). Deleted rather than archived: moving them under `research/` would have
put 897 lines of untyped orchestration code inside `ruff`/`mypy` scope for no reader. Git history keeps
them (present through 39ec603, the HEAD this step was made against). `.team/` stays in `.gitignore`;
the six `agent/*` worktrees registered under `.team/worktrees/` are runtime state for the maintainer to
remove with `git worktree remove` and `git branch -D agent/<name>`.
